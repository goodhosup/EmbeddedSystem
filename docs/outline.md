# 전체 목차

목차는 난이도로 나누지 않고 주제의 흐름을 따릅니다. 앞 장의 내용이 뒤 장의 바탕이 되도록 배치했기 때문에, 처음부터 읽으면 자연스럽게 기초에서 실무 수준까지 올라가게 됩니다. 이미 아는 부분은 건너뛰고 필요한 장부터 읽어도 됩니다.

## 실습 보드와 역할

| 보드 | 칩 | 맡는 역할 | 주로 쓰는 장 |
| --- | --- | --- | --- |
| 아두이노 우노 | ATmega328P (AVR 8비트, 16 MHz) | 입문. 아두이노 함수로 시작해 같은 동작을 레지스터로 다시 만든다 | 1~16장 |
| ATmega128 | ATmega128A (AVR 8비트, 16 MHz) | 우노와 다른 점(포트 수, UART 2개, 외부 메모리, ISP 프로그래밍)을 박스로 짚는다 | 5~16장 박스 |
| STM32 | STM32F411RE (Arm Cortex-M4F 32비트, 100 MHz), NUCLEO-F411RE | 주변장치와 기본 통신은 AVR과 나란히 비교하고, 그 뒤 심화 내용은 전부 맡는다 | 3~36장 |
| ESP32 | ESP32 (Xtensa 듀얼코어 32비트, 240 MHz), ESP32-DevKitC | 무선, IoT, OTA. 아두이노 IDE로 시작해 ESP-IDF로 넘어간다 | 19~20장, 32장, 40장 |

주변장치와 기본 통신 장(6~16장)은 같은 구조를 따릅니다: 개념과 그림 → AVR(우노) 레지스터로 구현 → 같은 기능을 STM32로 구현 → 8비트와 32비트의 차이 정리. 장 제목 아래의 "실습"은 그 장에서 쓰는 보드입니다.

각 장 아래에는 다루는 내용과 그 장에 들어갈 그림 목록을 적었습니다. 그림 번호는 `그림 장-순번` 형식이고, 파일은 `figures/chNN/` 아래에 SVG로 둡니다. 통신 장(제3부)은 신호가 시간에 따라 어떻게 움직이는지가 핵심이라 타이밍 다이어그램과 연결도를 특히 많이 넣습니다.

## 제1부 임베디드 시스템의 바탕

### 1장. 임베디드 시스템이란 무엇인가
- 정의와 주변의 예시, 범용 컴퓨터와의 차이, 구성 요소, MCU와 MPU, 실시간성(하드/소프트), 자원 제약, 개발 흐름, 이 책의 실습 보드 네 가지
- 실습: 우노 (세 보드와 ESP32 소개)
- 그림
  - 1-1 임베디드 시스템의 구성 요소 (센서 → MCU → 액추에이터, 전원, 통신)
  - 1-2 MCU와 MPU 비교 (칩 하나에 모든 것 vs 외부 메모리와 운영체제)
  - 1-3 하드 실시간과 소프트 실시간의 마감 시간 비교
  - 1-4 펌웨어 개발 흐름 (작성 → 크로스 컴파일 → 플래싱 → 디버깅)
  - 1-5 이 책의 실습 보드 네 가지와 역할
  - 1-6 digitalWrite(13, HIGH) 한 줄이 실제로 하는 일 (핀 번호 → PB5 → PORTB 비트)

### 2장. 하드웨어 기초: 회로와 데이터시트
- 전압·전류·저항, 디지털 논리 레벨, 풀업/풀다운, 푸시풀과 오픈 드레인, LED 전류 제한 저항, 브레드보드와 멀티미터, 데이터시트와 레퍼런스 매뉴얼
- 실습: 우노, 브레드보드, 멀티미터
- 그림
  - 2-1 옴의 법칙과 LED 회로
  - 2-2 논리 레벨과 노이즈 마진 (VIL, VIH, VOL, VOH)
  - 2-3 풀업과 풀다운 저항이 있는 버튼 회로
  - 2-4 푸시풀 출력과 오픈 드레인 출력의 내부 구조
  - 2-5 브레드보드 내부 연결 구조
  - 2-6 데이터시트 한 페이지 읽는 법 (표기 해설)

### 3장. 마이크로컨트롤러의 구조
- AVR 구조(하버드 구조, 범용 레지스터 32개, I/O 레지스터), Cortex-M 코어와 레지스터, 메모리 맵, Flash와 SRAM, 버스(AHB/APB), 클럭 트리와 PLL, 리셋 소스, CMSIS, 8비트와 32비트 MCU 비교
- 실습: 우노(ATmega328P)와 STM32 구조 비교
- 그림
  - 3-1 ATmega328P 블록 다이어그램 (단순화)
  - 3-2 STM32F411 블록 다이어그램 (단순화)
  - 3-3 코어 레지스터 (R0~R15, xPSR)
  - 3-4 AVR의 하버드 구조와 Cortex-M의 단일 메모리 맵 비교
  - 3-5 Cortex-M 메모리 맵 (코드, SRAM, 주변장치 영역)
  - 3-6 버스 구조 (코어 – 버스 매트릭스 – AHB/APB – 주변장치)
  - 3-7 클럭 트리 (HSI/HSE → PLL → SYSCLK → AHB/APB 분주)

### 4장. 임베디드를 위한 C 언어
- 고정폭 정수, 비트 연산과 마스크, `volatile`과 `const`, 포인터로 메모리 주소 다루기, 구조체로 레지스터 맵 표현하기, 정수 승격과 부호 함정, 비트 필드의 위험
- 실습: 우노, STM32
- 그림
  - 4-1 비트 설정·해제·반전·검사 연산을 비트열로 표현
  - 4-2 `volatile`이 없을 때 컴파일러가 루프를 지워 버리는 과정
  - 4-3 레지스터 주소와 구조체 멤버가 겹쳐지는 모습

### 5장. 개발 환경 구축: 아두이노에서 레지스터까지
- 아두이노 IDE로 첫 프로그램, 같은 프로그램을 avr-gcc와 avrdude로 빌드하고 올리기, ATmega128과 ISP 프로그래머, Arm GNU Toolchain·CMake·OpenOCD로 STM32 빌드와 디버깅, ESP32 개발 환경(아두이노 IDE, ESP-IDF), VS Code 설정
- 실습: 우노(아두이노 IDE, avr-gcc + avrdude), ATmega128(USBasp ISP), STM32(arm-none-eabi-gcc, OpenOCD), ESP32(아두이노 IDE, ESP-IDF)
- 그림
  - 5-1 보드별 업로드 경로 비교 (우노 부트로더, ATmega128 ISP, STM32 ST-LINK SWD, ESP32 USB-UART)
  - 5-2 툴체인 구성 (컴파일러, 링커, objcopy, OpenOCD, GDB의 역할)
  - 5-3 아두이노 IDE가 내부에서 하는 일 (스케치 → avr-gcc → avrdude)
  - 5-4 USBasp와 ATmega128 ISP 연결도
  - 5-5 VS Code 디버그 화면 안내

- 그림

- 그림
