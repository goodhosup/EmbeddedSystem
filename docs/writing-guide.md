# 집필 가이드

모든 장이 같은 목소리와 구조를 갖도록 지키는 규칙입니다.

## 장 구성 템플릿

1. **이 장에서 배우는 것**: 3~5개 항목의 학습 목표
2. **본문**: 개념 → 그림/표 → 코드 → 실습 순서
3. **정리**: 핵심 내용 요약 (5줄 내외)
4. **연습 문제**: 개념 확인 문제와 실습 과제를 섞어 3~6개
5. **더 알아보기** (선택): 심화 주제와 참고 자료

## 문체

- 존댓말 평서문("~합니다")을 씁니다.
- 한 문단에는 한 가지 생각만 담습니다.
- 처음 나오는 용어는 `한국어(English)` 형태로 쓰고, 이후에는 업계에서 더 흔히 쓰는 쪽을 씁니다. 예: 인터럽트, 레지스터, 펌웨어처럼 음차가 굳어진 말은 그대로 씁니다.
- "간단히", "쉽게"처럼 독자를 주눅 들게 할 수 있는 표현은 피합니다.

## 박스 표기

본문 사이에 아래 형식의 인용 박스를 씁니다.

- `> 💡 팁:` 알아 두면 편한 요령
- `> ⚠️ 주의:` 보드를 망가뜨리거나 디버깅 지옥에 빠지는 실수
- `> 🔧 ATmega128에서는:` 우노(ATmega328P)와 다른 점
- `> 🔍 깊이 보기:` 한 걸음 더 들어가는 심화 내용 (처음 읽을 때는 건너뛰어도 흐름이 끊기지 않게 씀)

## 그림

- 개념이 공간(연결, 구조)이나 시간(신호, 순서)을 다루면 글보다 그림을 먼저 보여 줍니다.
- 통신 장은 다음 세 가지 그림을 기본으로 갖춥니다: 연결도(어떤 선을 어디에), 프레임/패킷 구조, 타이밍 다이어그램(실제 비트가 선 위에 나타나는 모양).
- 그림 번호는 `그림 장-순번`, 파일 이름은 `figures/chNN/figN-M-주제.svg`입니다. 본문에서는 `![그림 N-M 제목](../figures/chNN/파일.svg)`로 넣습니다.
- 그림은 `tools/figgen.py`로 생성합니다. 색은 스크립트에 정의된 팔레트만 씁니다: 파랑(마스터/송신 측), 주황(슬레이브/수신 측), 초록(버스 조건, 시작/정지), 빨강(주의, 샘플링 시점), 회색(보조 설명).
- 배경은 흰색으로 고정해 GitHub 다크 모드에서도 잘 보이게 합니다.
- 그림 아래 한 줄 설명에는 그림에서 가장 중요한 한 가지를 씁니다.

## 보드별 서술 규칙

- 6~16장은 "개념과 그림 → 우노(AVR) 레지스터 구현 → STM32 구현 → 8비트와 32비트 비교" 순서로 씁니다.
- ATmega128은 본문을 따로 쓰지 않고 `> 🔧 ATmega128에서는:` 박스로 우노와 다른 점만 적습니다.
- ESP32는 19·20·32·40장에서 씁니다. 처음에는 아두이노 IDE, 이어서 ESP-IDF로 같은 기능을 다시 만듭니다.

## 코드

- 예제는 C11 기준입니다. AVR은 `avr-gcc`, STM32는 `arm-none-eabi-gcc`, ESP32는 ESP-IDF로 빌드됩니다.
- 본문의 코드 조각은 `code/chNN-주제/` 아래의 실제로 빌드되는 프로젝트에서 가져옵니다.
- 레지스터 주소와 비트 위치에는 출처 문서와 절 번호를 주석으로 남깁니다 (ATmega328P 데이터시트, ATmega128A 데이터시트, STM32F411 RM0383, ESP32 TRM).
- 들여쓰기 4칸, 중괄호는 K&R 스타일을 씁니다.
