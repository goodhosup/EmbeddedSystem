# 설계 문서: 환경 모니터링 데이터 로거

30장 프로젝트의 설계 문서입니다. 본문 30.2절에서 각 항목을 쓰는 이유를 설명합니다.

## 1. 목적

실내 온도를 정해진 주기로 재서 SD 카드에 CSV 파일로 남긴다. 사용자는 카드를 빼서 PC의 스프레드시트로 연다.

## 2. 요구 사항

| 번호 | 요구 사항 | 확인 방법 |
| --- | --- | --- |
| R1 | 1초(설정에 따라 10초)마다 온도를 0.01 °C 단위로 기록한다 | 파일의 seq, uptime_s 간격 |
| R2 | 기록은 CSV(머리줄 + 한 줄에 한 기록)로, PC에서 바로 열린다 | 스프레드시트로 열기 |
| R3 | 전원이 갑자기 끊겨도 최대 10개 기록만 잃는다 | PC 테스트 `test_power_loss`, 보드에서 전원 차단 시험 |
| R4 | 켤 때마다 새 파일(LOG00001.CSV, LOG00002.CSV …)에 쓰고 지난 파일을 덮어쓰지 않는다 | PC 테스트 `test_logger` |
| R5 | 센서 오류는 기록에 표시하고(값 칸 비움, flags = 1) 기록을 계속한다 | 센서 선을 뽑고 다시 꽂기 |
| R6 | SD 카드가 없거나 빠져도 멈추지 않고, 5초마다 다시 시도한다 | 카드를 뺐다 꽂기 |
| R7 | 측정 주기는 SD 카드 쓰기에 영향받지 않는다. 기록을 버리면 다음 기록에 표시한다(flags = 2) | `s` 명령의 dropped |
| R8 | 사용자는 UART 명령으로 상태 확인, 강제 저장, 안전한 카드 제거를 할 수 있다 | `s`, `f`, `x`, `r` |

범위 밖: 시각(RTC, 11장), 습도와 기압, 무선 전송(19·20장), 배터리 수명 최적화(STOP 모드)

## 3. 하드웨어

| 부품 | 연결 | 비고 |
| --- | --- | --- |
| NUCLEO-F411RE | | HSI 16 MHz |
| BMP280 모듈 | I2C1 PB8/PB9, 0x76, 3.3 V | 15장 |
| microSD 모듈 (SPI) | SPI1 PA5/PA6/PA7, CS PB6, 3.3 V | 16장. 5 V 레벨 변환기가 있는 모듈은 3.3 V 전원 확인 |
| UART | USART2 → ST-LINK 가상 COM | 115200 bps |

PA5는 LD2와 같은 핀이므로 LED를 쓰지 않는다.

## 4. 소프트웨어 구조

| 계층 | 모듈 | PC에서 시험 |
| --- | --- | --- |
| 앱 | `stm32/main.c` (태스크) | 아니요 |
| 서비스 | `common/logger.c`, `common/logrec.c` | 예 |
| 파일 시스템 | FatFs R0.15a (`ffconf.h`) | 예 |
| 드라이버 | `common/sd_spi.c`, `common/diskio.c`, 15장 `bmp280.c` | 예 (가짜 SD 카드) |
| HAL | 15장 `i2c_stm32.c`, 16장 `spi_stm32.c`, `stm32/uart_dma.c` | 아니요 (가짜로 대체) |

### 태스크

| 태스크 | 우선순위 | 주기/계기 | 소유 자원 | 스택 (워드) |
| --- | --- | --- | --- | --- |
| sensor | 3 | 1 s 또는 10 s (`vTaskDelayUntil`) | I2C1, BMP280 | 384 |
| logger | 2 | `msg_q` 수신 | SPI1, SD, FatFs | 768 |
| console | 1 | UART 수신 큐 | 없음 (명령은 `msg_q`로 보냄) | 512 |

규칙: 각 하드웨어 자원은 한 태스크만 쓴다(27장의 소유권). 다른 태스크는 큐로 요청한다. 그래서 뮤텍스가 필요한 곳은 UART 송신(`uart_dma.c`) 하나뿐이다.

### 큐

- `msg_q`: 길이 16, 항목 `msg_t`(기록 또는 명령). sensor는 기다리지 않고 넣는다(R7).
- UART 수신 큐: 길이 32, `char`.

## 5. 데이터 형식

```
seq,uptime_s,temp_c,flags
0,1,24.87,0
1,2,24.88,0
2,3,,1
```

flags: 비트 0 = 센서 오류, 비트 1 = 이 기록 앞에서 기록을 버림.

## 6. 오류 처리

| 상황 | 동작 |
| --- | --- |
| 센서 응답 없음 | flags = 1로 기록, I2C 버스 복구, 다음 주기에 다시 초기화 |
| 카드 없음, 마운트 실패 | 5초마다 다시 시도. 그동안의 기록은 큐가 차면 버림(flags = 2) |
| 쓰기 실패 | 파일을 닫고 마운트 다시 시도 (새 파일) |
| 큐 가득 참 | 버린 수를 세고 다음 기록에 표시 |
| 스택 넘침, 힙 부족, assert | 폴링 출력 후 멈춤 (35장에서 워치독 리셋으로 바꿀 것) |

## 7. 전력 (예시, 실측 필요)

| 상태 | 시간 비율 (1 s 주기) | 전류 |
| --- | --- | --- |
| 잠 (틱 없는 Idle, WFI) | 대부분 | 수 mA (MCU) + SD 대기 전류 |
| 측정 (I2C) | 약 1 ms | + BMP280 측정 전류 |
| SD 쓰기 (10줄마다 sync) | 수 ms ~ 수십 ms | 수십 mA 순간 전류 |
